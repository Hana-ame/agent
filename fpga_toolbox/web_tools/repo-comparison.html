控制面与验证面：fpga_toolbox 与 agent/verilog 是互补的两半

两个仓库并非同一问题的竞争方案。fpga_toolbox 解决的是 AI Agent 如何安全接入、解析并标准化驱动任意 RTL 仓库的「控制面」问题；agent/verilog 解决的是如何用真实 EDA 工具链与反假通过护栏证明一套 AXI4-Lite↔APB 硬件设计真正无缺陷的「验证面」问题。

两条路线分别站在验证栈的上下游，几乎没有代码重叠

如果把现代 AI 辅助 FPGA 验证拆成上下两层，fpga_toolbox 是一层干净、可复用、跨平台的工具编排与契约外壳：它用 14 个 Python 模块把「索引仓库 → 依赖闭包 → 沙箱隔离 → 接口抽取 → 契约校验 → 生成脚手架 → 结果归一化 → 看板渲染」封装成统一返回信封（ToolResult）和 MCP JSON Schema。它的核心设计目标不是把某一个 DUT 测到极致，而是让外部 Agent 能在不误删源码、不解析杂乱日志的前提下，稳定地调用标准化原语。

相反，agent/verilog（仓库 verilog 分支下的 verilog/ 目录）是一套在真实踩坑中长出来的重型硬件验证闭环。它直接面向 AXI4-Lite ↔ APB 串行/并发桥与寄存器文件，围绕 Verilator ≥ 5.040 + slang 构建了 9 关 CI、25 个测试套件、被动协议监视器、静态防竞争/防假通过检查器、变异测试框架以及由单一 JSON 规格生成的文档门户。两者在代码层面零交叉引用，恰好分别补齐对方的最大短板。

代码投入重心揭示了两者的本质差异

统计两个仓库去除缓存与生成 HTML 后的全部源码可以发现：agent/verilog 的 19,467 行代码中，真正的 RTL、接口与包定义仅占 10.2%（1,976 行），而用于测试平台、VIP、代码生成、静态 Lint、变异测试与 CI/审计的验证基础设施高达 16,676 行（85.7%）。反观 fpga_toolbox，总计 2,624 行代码全部聚焦在通用解析、契约校验、CLI/MCP 暴露与跨平台打包回归上，没有任何特定 DUT 或仿真器脚本。

八大工程维度逐项对照

下表从架构定位、依赖策略、RTL 解析、验证深度、反假通过机制到交付打包，对两套方案做直接横向拆解。

对比维度 fpga_toolbox（控制面工具箱） agent/verilog（重型验证工程）
核心定位 面向 AI Agent Harness / MCP Server 的通用原子工具集，按「读 RTL → 抽接口 → 验契约 → 生成 → 归一化 → 看板」拆成 8 个独立原语。 针对 AXI4-Lite ↔ APB 串行/并发桥与寄存器文件的完整硬件验证工程，追求高可信度、可复现、防静默通过。
调用接口与契约 三层入口（python -m fpga_toolbox、单文件直跑、Python API），自动生成 MCP JSON Schema，统一 ToolResult（ok/tool/data/diagnostics/error）。 面向人类与 CI 的命令行脚本（sim.sh、ci.sh、audit.sh、repro.sh），通过退出码和终端文本汇报，无 Agent/MCP 封装。
依赖与可移植性 纯 Python ≥ 3.10，仅依赖 PyYAML；GitHub Actions 实测覆盖 Ubuntu 与 Windows 矩阵，支持 wheel/sdist 打包发版。 强依赖 Verilator ≥ 5.040 + slang + matplotlib + Linux Bash 环境；内置幂等安装脚本 setup_env.sh（装至 ~/.local/verilator）。
RTL 语法解析 自研轻量级词法与递归下降解析器（sv_parser.py，313 行），零外部依赖、速度快，但不支持宏展开、generate 推导及 SV interface/modport。 前端编译校验直接交给工业级开源编译器 slang（完整 SV 语法/语义与 UVM 库检查），文档生成器则针对本项目 SV 约定做正则/结构提取。
协议与激励深度 接口分类支持 AXI4-Lite 与 AXI4-Stream；生成的 cocotb 仅覆盖复位值与非法地址响应，SVA 仅覆盖 VALID 稳定、复位响应、超时 3 类规则；反压与写掩码尚未消费。 覆盖 AXI4-Lite 与 APB 全链路：25 个测试套件、约 3,800 项检查、串行/并发双桥、参数扫掠（9 种子 × 9 wait）、独立被动协议监视器与 VIP/UVM-lite。
防假通过与质量门 聚焦工具自身正确性：tests/test_regression.py 校验沙箱误删防护、6 种复位命名、非法结果拒绝、CLI 契约与端到端链路；不含 RTL 变异或覆盖率门槛。 极强「反静默通过」体系：9 关 CI（覆盖率 ≥90%、变异得分 ≥80%、复现性、稳定性）、3 个静态反踩坑 Lint、33/33 变异全杀、8 项故障注入自审计（audit.sh）。
代码与文档生成 emit_testbench 从 YAML 契约生成 wrapper / SVA / bind / cocotb；render_visual_report 输出轻量依赖拓扑 SVG 与规则审计 HTML。 regfile_spec.json 单一事实源生成 RTL + TB + 寄存器手册，另有 5 个生成器产出 FSM / 接口映射 / 测试方案 / 覆盖率 / 门户共 6 份 HTML，并用 docs_check.py 校验一致性。
安全与状态隔离 copy_sandbox 具备硬性防误删契约：拒绝工程根/祖先/系统根/home 目录，仅清理带 .fpga_sandbox 标记的目录，保留相对层级与 SHA-256 校验。 repro.sh 通过干净 clone 验证无本地残留依赖；mutate.py 用 try/finally 强还原 RTL 并在检测到未还原变异时以 exit=4 拒绝运行。

八维能力成熟度几乎呈镜像分布

将两套方案在 8 个关键工程能力上按实测现状评分（0 = 空白，5 = 生产级完备），最直观的结论是：几乎每一项在左侧得高分的能力，在右侧都处于空白或初级状态，反之亦然。这意味着两者不是「二选一」，而是「拼图的两半」。

跨库实测暴露了 fpga_toolbox 的真实解析边界

我们直接在本机用 fpga_toolbox（回归测试全部通过）的 index_repo 和 extract_interfaces 工具去解析 agent/verilog 中的真实 RTL 文件。index_repo 成功扫描出全部 40 个模块，但在进入接口抽取阶段后，两组不同风格的 SystemVerilog 写法立刻暴露出决定性的边界差异。

对于传统的扁平端口模块（axi_apb_bridge.sv），fpga_toolbox 精准抽出了时钟 ACLK、复位 ARESETn、全部参数以及 16 个 AXI4-Lite 从机信号，仅将 8 个 APB 信号归入越界端口（因尚未内置 APB 分类器）。但一旦遇到现代 SV 的 interface + modport 写法（如 axi_apb_bridge_sv.sv），sv_parser.py 无法展开接口定义，反而把 axi、apb 接口参数误判为 1-bit 输入端口并赋予 tie_off: 1'b0——这会导致下游生成的 wrapper 无法编译。

agent/verilog 沉淀出的四项「反假通过」护栏最值得抽象

AI Agent 写硬件验证最危险的失效模式不是「编译报错」，而是「测试全绿但其实没测到」。agent/verilog 在 130 余次迭代中踩过 8 次静默通过、5 次 AXI 握手卡死和多次时钟沿竞争，最终沉淀出四套极具通用价值的工程护栏——这正是 fpga_toolbox 走向生产级 Agent 验证最缺的底座。

1. 三套静态反踩坑 Lint

lint_clocking.py 拦截时钟沿处紧邻阻塞赋值引发的采样竞争；lint_handshake.py 拦截只看 VALID 不看 READY 或同拍撤销 READY 导致的握手死锁；lint_silent_pass.py 专门抓空实现、SKIP 返回 0、只数 PASS 总数不核对身份等假通过写法。

2. 带强还原保护的变异测试闭环

mutate.py 对 RTL 注入定向运算符/常量变异并重跑测试，以「变异得分 = 杀死数 / 总数」量化测试集真实灵敏度（当前 33/33 = 100%）。更关键的是它内置 try/finally 强还原与残留检测（检测到未还原变异直接以 exit=4 拒绝执行）。

3. 故障注入式验证自审计（A1–A8）

audit.sh 不假设脚本本身可靠，而是主动向单套件、全量回归、CI 关卡、变异框架和覆盖率阈值注入 8 类故障，验证「失败时必须非零退出且保留诊断输出（配合 stdbuf 防挂死丢日志）」，闭环确认整个验证链路不会静默吞错。

4. 单一事实源 + 文档一致性校验

由 regfile_spec.json 统一派生 RTL、测试平台与寄存器手册，并用 docs_check.py 自动核对模块清单、测试项数、套件总数与废弃工具残留，防止代码演进后文档与契约悄悄漂移。

融合演进路线：用 fpga_toolbox 做壳，把 agent/verilog 抽成插件

两个仓库完全不必推倒重来。最优策略是以 fpga_toolbox 的 MCP/CLI 控制面与 ToolResult 契约作为统一入口，按 P0 → P1 → P2 三个阶段，把 agent/verilog 验证过有效的核心能力解耦成可选后端和新增原子工具。

P0 · 打通现代 SV 工程

  • 为 sv_parser.py 增加可选 slang AST 后端（检测到本机有 slang --ast-json 时自动启用），彻底解决 interface/modport、package 与宏展开问题。
  • 在 iface_extractor.py 补齐 APB 协议分类器，使 axi_apb_bridge 类双总线桥不再把 APB 侧误丢进越界端口。
  • 将 agent/verilog/axi/ 纳入 fpga_toolbox 的跨库集成回归集，作为真实复杂 RTL 基准。

P1 · 补齐执行与反静默护栏

  • 新增 run_sim 原子工具：吸收 vlt_env.sh 的 Verilator ≥ 5.040 版本探测与 stdbuf 输出保活，输出结构化日志给 normalize_sim_result。
  • 新增 lint_tb 原子工具：直接将 lint_clocking、lint_handshake、lint_silent_pass 封装进 ToolResult 诊断信封。
  • 新增 run_mutation 原子工具：将 mutate.py 的变异规则表参数化，保留 try/finally 强还原与残留退出码防护。

P2 · 统一契约与单一事实源

  • 对齐 fpga_toolbox 的 YAML 边界契约与 agent/verilog 的 regfile_spec.json（补齐 RO/RW/W1C/W1S/RC 字段与位域属性）。
  • 补全 emit_testbench 对 write_mask、random_backpressure 与 iterations 的代码生成，吸收 startup → drain → finalize 生命周期模板。
  • 把 docs_check.py 的一致性校验逻辑合入 render_visual_report，防止生成看板与真实测试项脱节。

fpga_toolbox 决定了 Agent 能不能「安全地上手任何芯片仓库」，agent/verilog 决定了验证结果「值不值得相信」——把后者的反假通过引擎装进前者的原子工具壳里，才是一套真正能交付的 AI FPGA 验证系统。
