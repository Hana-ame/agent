## 趋势分析

### 1. 格式层检测（wrong_operator 分离度）
- **1 层太弱**（0.93~1.41）：单层自注意力无法可靠编码"运算符位置错误"。
- **2~4 层是甜点**（3.0~4.4）：L2_D128=3.73、L4_D128=3.88、L4_D256=4.40。
- 超过 4 层无明显增益（L6 与 L4 接近），D=256 欠训练时 L6 反而回落（3.10）。

### 2. a<b 规则（negative_result 分离度）
- 强依赖层数：1 层 0.36~0.58（学不到），2 层跳到 1.7~2.2，L4_D128 达峰 2.23。
- 层数不是越多越好：L6_D128 回落到 1.40。

### 3. 算术对错（wrong_result 分离度）
- **全部 12 个配置 ≈ 0**（-0.02 ~ +0.01）：无论参数量/层数，tiny transformer
  都检不出"结果算错"。这是本研究最一致的负结果——格式与算术是两种能力。

### 4. 算术完成度
- **1 位减法**：随容量单调提升 12%→44%（L6_D128 最佳；D=256 欠训练时 L6 异常回落 11%）。
- **1 位加法**：同样随容量提升 2%→34%（L6_D128 最佳）。
- **2 位 / 4 位**：**全部 ≈0%**——进位推理在 ≤5M 参数、4000 步内完全未学会。

### 5. 综合
- **D=128 是该任务性价比甜点**：L4_D128（926K）/ L6_D128（1.3M）在格式检测与
  1 位算术上取得最佳平衡，且 4000 步仅需 3~8 分钟。
- 参数量主要买的是**算术能力**（1 位），对**格式检测**提升有限（L1→L2 是最大跳跃）。
- 增大参数量无法突破"多位进位算术"这道墙（2/4 位恒为 0）。

## 可复现

```bash
# D=64 / D=128 组（4000 步）
python -m additive_rand_transformer.scan --only L1_D64,L2_D64,L4_D64,L6_D64 --root runs/scan_A --steps 4000
python -m additive_rand_transformer.scan --only L1_D128,L2_D128,L4_D128,L6_D128 --root runs/scan_B --steps 4000
# D=256 组（2000 步）
python -m additive_rand_transformer.scan --only L1_D256,L2_D256,L4_D256,L6_D256 --root runs/scan_C --steps 2000
```
