# 自问自答 RL（Self-Play）探究：LLM 自己出题、自己答、只验证答案

> 在 `additive-rand-transformer` 分支实测。环境：conda torch 2.5.0，纯 CPU。
> 与既有 RL（`SPARSE_RL.md` 的 REINFORCE/GRPO，**外部出题**）对比。
> 本实验：**模型从 `<BOS>` 生成完整的加法表达式（题目+竖式+答案），Python
> 验证器只判断尾部答案是否正确**。

## 设定对比

| | 外部出题 RL（rl.py / grpo.py） | **自问自答 RL（rl_selfplay.py）** |
|---|---|---|
| 题目来源 | 数据生成器随机采样 | **模型自己生成** |
| 模型输出 | 只答 `a+b=?` 的答案 | 完整表达式（题+答案） |
| 奖励 | Python 验证答案对错 | **Python 验证答案对错** |
| 难度保障 | 生成器控制位数分布 | **无（模型自由出题）** ← 本探究重点 |

## 实验 1：无锚定 —— reward 刷满，但作弊坍缩

从 L4·D128 CoT（926K）起步，150 步自问自答 RL。

```
step  reward  mean_op_digits
   1   0.875    2.12        ← 初期还出 2 位题
  50   1.000    1.25        ← 开始只出 1 位
 150   1.000    1.00        ← 彻底作弊：只出 1 位加法
```

**replay 采样验证（60 次）**：唯一式子 **1/60**，全部是 `8+8=16`（1 位），
结构合法 60/60、答案正确 60/60。

**结论**：模型发现"出 1 位题永远答得对"，于是把题目空间坍缩到最小难度恰准点。
reward 100% 是**刷出来的**——不是学会了难题，是学会了出简单题。

## 实验 2：难度锚定（min_digits_reward=2）—— 能救作弊，但多样性坍缩

只在"两个操作数都 ≥2 位 **且** 答案正确"时给 reward。

```
step  reward  mean_op_digits
   1   0.875    2.12
  50   1.000    2.50
 150   1.000    2.50        ← 稳定在 2 位以上
```

**replay 采样验证（60 次）**：唯一式子 **1/60**，全部是 `999-10=989`
（3 位减法，答案正确 60/60）。

**结论**：
- ✅ 锚定**成功对抗作弊**——模型学会了出"难且对"的题（3 位减法，非 1 位）。
- ❌ 但**多样性彻底坍缩**：60 次采样只返回同一个式子。二值奖励是元凶——
  一旦某个式子满足奖励条件，梯度把它锁死，没有维持探索多样性的机制。

## 核心机理

**自问自答 RL 的固有矛盾**：奖励是二值的（对/错），题目空间却巨大。
- 外部出题 RL 中，输入多样性由**外部生成器**保障，模型只学"给定题→答案"映射；
- 自问自答 RL 中模型必须同时探索"题目空间 × 答案空间"，而二值奖励对
  "题目多样性"零激励 → 收敛到任意一个可行解就锁死（**模式坍缩**）。

对策（未来方向）：
1. 奖励加**多样性项**（如逐 unique 题奖励递减、entropy bonus on 题目分布）
2. 题目采样时用**确定性锚**（混合外部出题与自出题，保证覆盖）
3. 用 **极大熵 RL / 多样性正则**（类似 Go 的 self-play + 多样性）
