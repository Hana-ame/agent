## 关键结论

### 1. 数据形态是决定性的，规模只是放大器
- **plain 任意规模（117K~3.4M）：add2/3/4 全部 0-2%**——不换数据形态，加大模型无济于事。
- **cot 从 L1·D128 起就突破**：add1 97%、add2 67%——不需要大模型，需要正确的任务分解。
- 同一规模下 cot 的 loss（0.21-0.59）远低于 plain（1.04-1.14）：CoT 把难题切成
  "个位加法 + 进位"小步，每步都可预测。

### 2. d（宽度）比层数更关键
固定 1 层，看 d 的作用（cot）：
```
D64  -> add2  0%
D128 -> add2 67%
D256 -> add2 87%
```
**D64 是个坎**：任何层数下 D64 的多位几乎学不会（L4·D64 add2 也才 43%）。
D≥128 后层数差异变小（L1_D256 ≈ L2_D128 ≈ L4_D128）。

### 3. L1·D256 是意外亮点
单层 + 宽 embedding（1.1M 参数）在 cot 下 add1 98% / add2 87% / add3 70%，
优于更深的 L4·D128。说明该任务需要的不是"深度推理"而是"宽度记忆列式模式"。

### 4. 减法普遍比加法容易（溢出方向不同）
sub1 在多数 cot 配置下 100%（plain 最高 77%），因为减法不产生进位，列与列独立。
加法需要跨列传播进位，是真正的难点（add4 受限的根源）。

### 5. add4 的局限（数据问题，非模型）
所有 cot 配置 add4 只有 15-27%：原因是均匀位数采样时"4位+4位溢出到5位"样本
仅占 ~2%（`four_digit_bias=0.5` 提到 16%，见 COT.md 的偏置实验，可把 4 位结果
准确率从 76% 提到 94%，但 5 位溢出仍难）。

| 需求 | 配置 | 参数量 | 训练耗时 | add1-3 表现 |
|------|------|--------|---------|------------|
| 最省 | L1·D128 cot | 332K | ~3 min | add1 97% / add2 67% / add3 33% |

## 可复现

```bash
# 每个 (layer, d) 各训 plain 与 cot，同一协议
python -m additive_rand_transformer.scan_cot_vs_plain --mode plain --only L1_D64,... --steps 3000
python -m additive_rand_transformer.scan_cot_vs_plain --mode cot   --only L1_D64,... --steps 3000
# 从 checkpoint 统一重评估（生成 cot_vs_plain_final.json）
python -m additive_rand_transformer.eval_cot_vs_plain
```
