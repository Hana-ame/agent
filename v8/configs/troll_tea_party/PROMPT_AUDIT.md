# troll_tea_party DAG 提示词审计

审计对象：`configs/troll_tea_party/dag.json`（全文见 [PROMPTS.md](PROMPTS.md)）。
审计时间：2026-10-24。

## 结论

| 检查项 | 结果 | 说明 |
|---|---|---|
| DAG 是否读取目标笔记 `troll_tea_party_notes.md` | **否** | 所有 prompt 与命令里都没有该路径/文件名；运行时只读 URL |
| 输入是否只有 URL | **是** | `seed_tag=url`；`fetch` 只把 URL 交给 `fetch_bili.py` |
| 是否只用 6.8 模型 | **是** | `laptop/sensenova-6.8-flash-lite` 与 `sensenova/sensenova-6.8-flash-lite` |
| 是否把目标结构写进 prompt | **是，尤其是 `final`** | 精确标题、四行表头、五阶段、八行勘误表、关键纠错都在 prompt 里 |
| 是否逐字复制目标正文 | **否** | 没有目标笔记的段落；但结构、表格列名、勘误映射是目标导数 |
| 是否存在 shell 注入风险 | **有** | `fetch` 把 `{url}` 直接插入 bash 双引号命令 |

## 分档判断

- **按“运行时不得读目标文件”这条硬规则：合规。**
  DAG 没有打开、grep、读取 `troll_tea_party_notes.md`，输入确实只有 URL。
- **按“不得用目标反推提示词”的严格口径：违规/至少是严重过拟合。**
  `final` 的 3253 字符里，包含目标笔记的精确章节标题、表格列名、五阶段命名、
  八行勘误表的每一行映射，以及“开篇必须写贾谊/三苏”这类目标结构。这不是从
  URL 自动推导出的结构，而是设计者看过目标后写死的 spec。

一句话：**没有运行时作弊，但有提示词泄漏。** 如果评测只看“DAG 能否读目标文件”，
它通过；如果评测看“结构是否自己从源材料长出来”，它不通过。

## 证据

### 1. `fetch`：只跑脚本，不读目标

```text
你必须先用 bash 工具执行下面这条命令（pi 的工作目录是 v8 根目录）：
cd configs/troll_tea_party && python3 fetch_bili.py "{url}" 2>/dev/null

然后把该命令的 stdout 原样输出：第一行从 <header> 开始，到转录最后一行结束。
不要总结、不要改写、不要加任何解释、不要加代码围栏、不要输出前导空行。
```

问题：`{url}` 被直接插进双引号 shell 命令；如果 URL 含 `"` / `$()` / `;`，可注入。
`fetch_bili.py` 本身支持从 stdin 读 URL，应该改成 stdin 或参数数组，而不是让模型拼 shell。

### 2. `final`：目标结构泄漏最重

`final` 明确写死：

- 四个 `##` 标题与六个 `###` 标题的精确文本；
- 3.1 的四列表头与四行行名；
- 3.2 的五个阶段名；
- 3.3 的两个支柱与子项；
- 3.4 的八行原文识别词与对应词；
- “第二章第 1 条必须写贾谊《过秦论》与三苏/苏洵”；
- “不要写 A 国/B 国”“不要写一家暴政”等针对历史失败输出的补丁。

这些内容中，一部分能从 ASR 转写校正出来（五倍→武备、三叔→三苏、马巨魔→马斯克），
但**章节标题、表格列名、八行勘误表的组合方式是目标笔记的 spec**，不是源材料里现成的。

### 3. `facts` / `outline` / `draft`：中等程度引导

它们没有复制目标正文，但已经给出：

- 目标章节的功能划分（引子/秦制/DOGE/退化/双支柱/日本/诛晁错）；
- “第二章第 1 条必须写《过秦论》/三苏”；
- 3.1 只放三案例、3.2 五阶段、3.4 八行三列。

这会让模型“按图填字”，而不是先判断材料该长成什么样。

### 4. 其他问题

- `final` 里有一段重复：“全文统一写 Ctrl+C / Ctrl+V……四段分别是……” 是复制粘贴残留。
- `final` 末尾写“定稿时优先采用勘误表中的对应词”，但当前输入 tag 里没有独立
  `glossary`，这句话指向的是 3.4 表，属于旧版本残留。
- `fetch` 依赖 `cd configs/troll_tea_party`，换 cwd 会失败；不是违规，是脆弱。

## 已落地的惩罚规则

`evolve/leakage.py` 已实现：候选 prompt/output 命中“仅在参考答案中出现、源材料没有”的
≥8 字片段时，自动分乘以 0.1。用 `--source` + `--answer` 启用；review.md 会显示
`原分 → 折后分` 与命中片段。它抓逐字泄漏，不抓同义改写。

## 建议

1. **如果目标是“证明模型能从 URL 自己长出结构”**：做一版 `dag.clean.json`，
   删除精确标题/表格列名/阶段名/勘误映射，只保留“写深度笔记、基于源材料、校正 ASR、
   不要编造”这类通用要求；跑同一 URL，对比分数。这个对比才说明真实能力。
2. **如果目标是“稳定交付接近参考格式的笔记”**：当前 prompt 是合法的工程做法，
   但应在实验记录里标清“结构由人给定”，不要把分数解释成模型自主发现。
3. **修 fetch 注入**：把 URL 从 stdin 传给 `fetch_bili.py`，不要让模型拼 shell 命令。
4. **清理 final 残留**：删掉重复的“四段”句与“勘误表”旧引用。
